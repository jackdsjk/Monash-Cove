# UI 迁移计划：Figma Make → webapp（2026-11-09）

## 目标

`webapp/` 的界面 1:1 换成 Figma Make 版本（`~/Downloads/Monash Student Change Tracker/`），功能接回本地服务；Make 版有而我们没有的功能，按同一套视觉语言补齐。

## 事实基线

| 项 | 现状 |
|---|---|
| Make 版 | React 19 + Vite 8 + Tailwind 4 + lucide-react，自定义 hash 路由，数据全部是 `src/data/seed.ts`、`workspace.ts` 里的静态 fixture，localStorage 持久化 |
| webapp 版 | React 19 + Vite 8 + Ant Design 6 + 手写 `styles.css`（3483 行），react-router-dom 7，数据来自 `/api` |
| 结论 | 视觉层整包替换；数据层保留 `src/data/repository.ts` 与 `/api`，另加一层 adapter 把 API 数据映射成 Make 的 `Item` / `ItemChange` / `SourceState` |

## 架构

```
webapp/src/
├── components/        ← 从 Make 原样搬运（ui.tsx、Shell、ItemDrawer、CommandPalette、LaunchSummary、RequireSource）
├── pages/             ← 从 Make 搬运，数据改为从 store/adapter 取
├── lib/               ← Make 的 router（hash 路由）、brief.ts、time.ts 等原样搬运
├── data/
│   ├── model.ts       ← Make 的类型定义
│   ├── adapter.ts     ← 新增：BriefItem → Item、ItemChange → ItemChange、SourceStatus → SourceState
│   └── repository.ts  ← 保留，API 客户端
├── store.tsx          ← 新增：保留 Make 的 Store 接口，实现改成从 /api 取数
├── index.css          ← Make 的主题（@theme 品牌色、动效）
└── styles.css         ← 迁移完成后删除
```

**关键约束**：`Store` 的公开接口保持与 Make 版完全一致，页面代码因此可以原样搬运、只改数据来源。任何页面都不得直接 `import` `seed.ts` / `workspace.ts`。

## 执行顺序

1. **基础**：依赖（tailwind v4、lucide）、`vite.config.ts` 加 `tailwindcss()`、`index.css`、搬运 `ui.tsx` / `Shell` / `router`。
2. **数据层**：`data/model.ts` + `data/adapter.ts` + 改写 `store.tsx`，对外接口不变。
3. **页面**：先 Brief，再其余页；每页一个独立文件，互不依赖。
4. **收尾**：删除 Ant Design 与 `styles.css`，`npm run check` 通过。

## 已知取舍

- Make 版的 `localStorage` 持久化保留，但只存 UI 偏好（已读标记、设置、上次查看时间），业务数据一律走 `/api`。
- Make 版里「演示用 Gmail 同步失败」这类假状态一律删除。
- `grades` 与 `pack` 两页先按 UI 落地，数据接口未就绪时显示明确的空态，不造假数据。
