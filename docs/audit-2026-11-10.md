## 优先问题：P1

### 01 · 所有来源断开时，首次设置无法继续

- **位置：** [App.tsx](../webapp/src/App.tsx#L24)，第 24–27、41 行。
- **触发：** 全新的浏览器存储，且来源均为 `disconnected`。应用跳到 `/setup`，实际只渲染 `ComingSoon`，没有连接、完成或跳过按钮；点击侧栏“来源”仍被重定向回去。
- **实测：** 浏览器重复点击来源后 URL 仍为 `#/setup`。截图：`screenshots/setup-repro.png`。
- **修复方向：** 接回设置向导，或让首次设置进入真实来源连接流程。默认 fixture 会被当作已连接，掩盖该问题；不能只测试示例启动。

### 02 · Gmail 增量历史只读取第一页

- **位置：** [sources/gmail.ts](../local-service/src/sources/gmail.ts#L96)，第 96 行附近；[sync/gmail.ts](../local-service/src/sync/gmail.ts#L74)，第 74 行。
- **触发：** Gmail history 返回 `nextPageToken`。客户端没有继续分页，却推进同步游标，后续普通增量无法补回遗漏项。
- **实测：** 第一页含 `first-page` 与下一页标记，第二页含 `second-page`；实际只请求一次，只返回 `first-page`。
- **修复方向：** 消费全部 history 分页并去重，完成入库后再保存相应检查点。

### 03 · 同步期间到达的新邮件可能被游标跳过

- **位置：** [sync/gmail.ts](../local-service/src/sync/gmail.ts#L74)，第 74 行。
- **触发：** 列出邮件 ID 后，下载与分类期间有新邮件到达。处理结束才读取最新 profile historyId，新邮件不在本轮集合里，却被新游标覆盖。
- **实测：** 处理 A 期间 B 到达，游标从 100 升为 200；连续两轮同步仍只有 `gmail:A`，B 未入库。
- **修复方向：** 固定本轮覆盖的游标边界，使用已完整消费的 history 检查点；全量同步也需衔接期间产生的增量。

### 04 · 来源报错后重启，重新注入示例并清除错误

- **位置：** [db.ts](../local-service/src/db.ts#L213)，第 213–255 行；[index.ts](../local-service/src/index.ts#L18)，第 18 行；[adapter.ts](../webapp/src/data/adapter.ts#L60)，第 60–75 行。
- **触发：** 已使用的来源变为 `error`、`degraded` 或 `disconnected` 后重开数据库。默认 seed 仅排除 `connected`，会对其他状态重新灌 fixture、改状态并清空错误。
- **实测：** Ed 为 `error / Expired token`，重开后变为 `fixture / lastError:null`，新增 25 条示例。前端又把 fixture 视为 connected/idle，显示“已同步”和可断开，无法明确分辨示例与真实数据。
- **修复方向：** 示例模式显式启用；生产启动不根据连接状态自动填示例；错误与用户断开状态必须保留；UI 明确标示示例。

### 05 · 切换 OnTrack 账号后，仍复用旧账号缓存

- **位置：** [sources/ontrack.ts](../local-service/src/sources/ontrack.ts#L181)，第 181–185、229–231 行。
- **触发：** 在同一站点从账号 A 切到 B。缓存只校验 baseUrl 与过期时间，没有核对 username/凭据版本，也未在切换时失效。
- **实测：** 存储已改为 B，读取账号仍为 A；换 token 仅调用一次。后续请求还可能组合 B 的 Username 与 A 的 token。
- **修复方向：** 缓存绑定账号与凭据版本，连接、断开、换账号时失效，并阻止旧请求写回。

### 06 · 刚同步到的旧内容不进入“自上次查看”

- **位置：** [adapter.ts](../webapp/src/data/adapter.ts#L21)，第 21 行；[BriefPage.tsx](../webapp/src/pages/BriefPage.tsx#L68)，第 68–78 行；[db.ts](../local-service/src/db.ts#L847)，第 847–861 行。
- **触发：** 源发布时间早于上次查看，但本轮才首次同步到。前端把 `publishedAt` 当作 `firstSeenAt`；数据库虽有 `first_seen_at`，返回 DTO 未暴露。
- **实测：** 11 月 10 日首次导入 11 月 8 日发布的条目，上次查看为 11 月 10 日 11:00；条目被排除出新增，详情“首次同步”也显示成源发布时间。
- **修复方向：** API 暴露真实首次入库时间；发布、首次发现、最后变化分别建模。

## 其他确认问题：P2

### 07 · 窄屏布局不可用

- **位置：** [Shell.tsx](../webapp/src/components/Shell.tsx#L67)，第 67、106 行；[BriefPage.tsx](../webapp/src/pages/BriefPage.tsx#L148)，第 148 行；页面标题操作栏。
- **实测：** 390px 窗口仍固定保留 256px 侧栏，主区域只剩 134px；标题被挤成竖排，筛选/同步/已查看按钮超出屏幕。截图：`screenshots/mobile-repro.png`，同目录保留桌面对照。
- **修复方向：** 给侧栏、页边距、操作栏及表格设置响应式布局；验证窄桌面、平板与手机，不能仅隐藏横向溢出来遮住按钮。

### 08 · 增量同步失败后，没有保留失败状态

- **位置：** [store.tsx](../webapp/src/store.tsx#L161)，第 161–172 行。
- **实测：** 中止四个 `/api/sync` 请求，页面仍显示“已同步”，没有失败提示。代码也未检查 `response.ok`；catch 写入 error 后，finally 无条件改为 idle 并更新成功时间。随后 refresh 可能还原后端时间，但不能保证保留这次请求的错误。
- **修复方向：** 检查 HTTP 状态，仅在成功路径更新时间；请求失败与数据刷新结果分别维护。

### 09 · “已提交”在详情与截止页使用不同状态

- **位置：** [ItemDrawer.tsx](../webapp/src/components/ItemDrawer.tsx#L154)，第 154–156 行；[DeadlinesPage.tsx](../webapp/src/pages/DeadlinesPage.tsx#L131)，第 131–139 行。
- **实测：** 合成条目由后端标为已完成，截止页显示“已提交”，打开详情后同名按钮 `aria-pressed=false`。详情只写浏览器 marks，截止页合并后端完成状态并调用 API；取消操作也可能在另一页恢复为完成。
- **修复方向：** 两个入口共同读取并更新同一完成状态；持久化成功后同步 Store，失败保留可见反馈。

### 10 · 时区设置不影响截止时间

- **位置：** [SettingsPage.tsx](../webapp/src/pages/SettingsPage.tsx#L142)，第 142–155 行；[time.ts](../webapp/src/lib/time.ts#L12)，第 12–30 行。
- **实测：** 宿主 UTC、设置 `Asia/Kuala_Lumpur` 时，`2026-11-10T12:00:00Z` 显示 `12:00`，应为 `20:00`。格式化直接取设备本地时间，没有消费设置。
- **修复方向：** 统一格式化入口，以 IANA 时区显式格式化；考试页已有独立时区逻辑，不能据此认为其他页面也正确。

### 11 · OnTrack 断开成功后，仍回退到 CLI 登录态

- **位置：** [app.ts](../local-service/src/app.ts#L906)，第 906 行附近；[sources/ontrack.ts](../local-service/src/sources/ontrack.ts#L189)，第 189、244 行。
- **实测：** 临时目录放假 CLI session，断开 API 返回 200，随后账号 API 仍返回 `connected:true`。删除 Cove 凭据后直接使用 CLI fallback，忽略主动断开的意图。
- **修复方向：** 在 Cove 内持久化主动断开状态、清理账号缓存；保留用户的 CLI 文件，停止自动回退。

### 12 · 全量同步把未连接来源当作失败，且没有覆盖文案中的四源

- **位置：** [app.ts](../local-service/src/app.ts#L1319)，第 1319–1377 行；[SettingsPage.tsx](../webapp/src/pages/SettingsPage.tsx)，全量同步说明。
- **实测：** 仅配置 Moodle 时，公开 HTTP 全量接口执行了 Moodle，模拟请求 5 次、Moodle 状态为 done；但未配置 Gmail/Ed 被计为 error，整体任务 error、`fullSyncCompleted:false`。此外该 handler 只运行 Gmail/Ed/Moodle，与页面包含 OnTrack 的“全部内容”说明不符。
- **修复方向：** 按已配置来源执行，区分 skipped/failed/done，按实际范围定义完成；统一文案与四源执行路径。
- **排除的误判：** 未使用的 `SyncOrchestrator.full()` 会在 Gmail 提前抛错，但公开 HTTP handler 独立隔离了各来源，不能报告成“Moodle 从未执行”。

### 13 · 当前 E2E 仍绑定旧界面，未验证新主流程

- **位置：** [smoke.mjs](../webapp/e2e/smoke.mjs#L49)，第 49 行及后续 `.command-trigger`、Ant Design Drawer/Modal、menuitem 定位。
- **实测：** `rtk npm run e2e` 在 `.item-card` 等待 30 秒后失败。当前入口已使用新 Shell、链接导航和自定义 Drawer，脚本未同步迁移。
- **修复方向：** 按当前用户可访问的角色与名称重写主流程；加入全断开、新入库旧文章、失败同步、完成状态及多窗口宽度。不要只把超时放宽。

### 14 · 详情弹窗没有接管或约束键盘焦点

- **位置：** [ItemDrawer.tsx](../webapp/src/components/ItemDrawer.tsx#L35)，第 35–44 行及弹窗生命周期。
- **实测：** 打开 `aria-modal=true` 的详情后焦点仍在背后的作业标题；按 Tab 后落到背景的“已提交”，仍不在 dialog 内。键盘操作可触达被遮挡内容。
- **修复方向：** 打开时移入焦点、约束 Tab、关闭后恢复焦点；优先复用成熟 dialog primitive。
